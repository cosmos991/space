# ASTERION — 자유 함장 시뮬레이션

단일 항성계에서 함교 HUD로 항해·탐사·교역·세력 통신·전초기지 운영을 진행하는 한국어 웹 게임입니다. 전투나 직접 조종 대신 목적지와 명령을 선택하는 지휘형 프로토타입입니다.

## 실행

Node.js 22 이상. 외부 패키지 설치가 필요 없습니다.

```sh
npm run dev
# http://localhost:3000
```

```sh
npm test
npm run build
```

## 첫 항해

1. 통신 탭에서 항성 연합의 보급 계약을 수락합니다.
2. 지도에서 테라 노바를 선택하고 출항합니다. 초기 식량 5t으로 첫 계약을 수행할 수 있습니다.
3. 1×/4×/12×로 시간을 진행합니다. 도착하면 자동으로 멈춥니다.
4. 통신 탭에서 화물을 전달하고 650 CR을 받습니다.
5. 항구에서 연료를 보급하고 다른 구역을 탐사하거나 교역합니다.
6. 케플러 소행성대를 탐사하고 2,000 CR으로 전초기지를 건설하면 시간당 9 CR을 받습니다.

항성 관측 궤도를 포함한 총 8개 목적지, 항구별 가격, 40t 화물 제한, 탐사별 보상, 반복 보급 계약, 긴급 구조 사건을 제공합니다. 구역 탐사는 3회까지 가능합니다. 외곽에서 연료가 떨어지면 긴급 예인으로 복귀할 수 있습니다. 자금이 없어도 예인되므로 진행이 막히지 않습니다.

## AI 통신 설정

키 없이도 규칙 기반 로컬 통신과 모든 게임 기능을 이용할 수 있습니다. 실제 AI 통신은 서버에서 OpenAI Responses API를 호출합니다. AI는 인물 대화와 안내를 담당하며 자산·계약·항로를 직접 변경하지 않습니다. 실행 가능한 계약은 HUD 버튼으로 확정합니다.

`.env.example`을 `.env`로 복사하고 아래 서버 환경 변수를 설정하세요. `.env`는 커밋하지 않습니다.

| 변수 | 용도 |
| --- | --- |
| `OPENAI_API_KEY` | OpenAI API 키. 브라우저에 전달하지 않습니다. |
| `OPENAI_MODEL` | 사용 가능한 모델 ID. 기본 `gpt-4.1-mini`. |
| `GAME_ACCESS_CODE` | 개인 AI 호출용 긴 임의 접근 코드. 키와 함께 설정해야 AI가 활성화됩니다. |

통신 패널의 **AI 통신 접근 코드**에 서버와 같은 코드를 입력합니다. 코드는 탭 세션에만 저장합니다. 대화는 최근 10개 메시지와 현재 게임 상태를 전송하며 API 요청은 자동 재시도하지 않습니다. 로컬 기본 제한은 IP당 분당 12회이며 서버리스 인스턴스 사이에는 공유되지 않습니다. 여러 사용자에게 AI 호출을 공개하려면 별도 계정 인증·공유 사용량 제한을 추가해야 합니다.

## Vercel

이 저장소를 Vercel에 연결하고 Framework Preset은 **Other**로 선택하세요. `vercel.json`에 빌드 명령과 출력 폴더가 설정되어 있습니다. `api/comms.js`는 서버 함수로 실행됩니다. AI를 사용할 경우 위 환경 변수를 프로젝트에 설정하고 다시 배포하세요. 별도 상시 서버는 필요 없습니다.

정적 호스팅만으로는 AI 통신 API가 실행되지 않습니다. 로컬에서는 반드시 `npm run dev` 서버를 이용하세요.

## 구조와 저장

- `engine.js`: 게임 상태와 규칙. AI와 독립적으로 동작합니다.
- `app.js` / `style.css` / `index.html`: 반응형 함교 HUD와 지도.
- `api/comms.js`: 입력 검증, 접근 코드 검증, AI/로컬 통신.
- `server.js`: 의존성 없는 개발 서버.
- `tests/`: 거래·항해·사건·계약·저장·통신 검증.

진행은 브라우저 localStorage에 자동 저장됩니다. 서버나 계정에 저장되지 않으며 다른 기기로 동기화하지 않습니다. 화면을 숨기거나 닫으면 시간이 정지합니다. 새 항해는 확인 후 현재 저장을 초기화합니다. 일반 글꼴은 오프라인 대체 글꼴로도 동작합니다.

현재 지원 범위는 개인 함선 1척, 채굴 전초기지, 조건부 행성 소유권, 주요 팩션별 신뢰와 명예입니다. 세부 행성 통치 정책, 함대, 자유 대화의 동적 계약 변환은 이후 확장 영역입니다.


## 거래소 확장

- 광물·식량·기술 부품을 1~40t 단위로 주문합니다. 1t/5t/10t/최대 수량 바로가기를 제공합니다.
- 항구별 유한 재고와 시세가 있습니다. 매수는 재고를 줄이고 가격을 올리며, 매도는 재고를 늘리고 가격을 낮춥니다. 전체 주문을 1t씩 계산하므로 대량 주문에도 가격 영향이 포함됩니다.
- 재고는 게임 시간 24시간마다 정상 수준을 향해 회복합니다. 시세는 날짜별로도 변합니다. 현실 시간이나 오프라인 시간은 반영하지 않습니다.
- 주문 금액·평균 체결가·매도 손익을 확인한 뒤 확정합니다. 시세가 바뀌면 주문을 갱신하고 다시 확인하도록 합니다.
- 화물의 가중 평균 매입 원가, 누적 교역 실현 손익, 거래 내역 60건을 저장합니다. 초기 화물과 탐사 회수품은 원가 0으로 처리합니다. 계약/구조에 쓴 화물은 원가도 제거하고 교역 손익에는 포함하지 않습니다.
- 5t 기준 교역 항로를 추천하고, 현재 편도 연료비를 차감한 예상 순익을 보여줍니다. 도착 시세 변동·귀환 비용·시간 기회비용은 별도입니다. 현재 자금·화물칸·재고로 살 수 있는 상품만 제안합니다.
- 항구별 원격 시세, 거래 내역, 화물 명세를 펼쳐 볼 수 있습니다. 원격 주문은 허용하지 않습니다.
- 기존 v1 저장을 그대로 불러오며, 기존 화물의 이전 매입 이력은 없으므로 원가 0에서 새 장부를 시작합니다.
- `economy.js`: 시장 계산과 원가/거래 장부. `trading-ui.js`: 거래소 HUD.

## 함교 화면과 독립 패널

기본 화면에는 항성계 지도, 작은 자원 표시, 현재 항로와 시간 조절만 표시합니다. 왼쪽 메뉴에서 거래소·자산·통신·함선·일지를 선택하면 전용 패널이 열립니다. 지도에서 목적지를 고르면 항법 패널이 열립니다. 패널 안의 메뉴로 다른 시스템으로 전환할 수 있습니다.

패널을 열면 시간이 정지하며 닫기·ESC·패널 바깥 클릭·하단의 돌아가기로 지도로 복귀합니다. 패널을 닫아도 시간이 자동 재개되지는 않습니다. 항법 패널에서 출항하면 패널이 닫히고 항해가 시작됩니다. 중요한 구조 사건은 대응 패널을 엽니다. 거래는 거래소 패널 안에서 수량과 금액을 확인한 후 실행합니다.

## 자동 배포

GitHub `main`과 Vercel 프로젝트가 연결되어 있으며 커밋하면 자동 배포됩니다. `vercel.json`의 배포 빌드 명령은 `npm test && npm run build`입니다. 테스트 실패 시 배포가 실패하고 기존 성공 버전이 유지됩니다. 작업 완료는 해당 커밋의 Vercel 성공 상태까지 확인합니다.

운영 주소: https://space-gamma-wheat.vercel.app

## 함선 이미지와 API 사용량

CSV 노마드의 생성형 함선 아트를 `assets/nomad.jpg`로 제공합니다. 함선 패널의 대표 이미지와 자산 카드에서 볼 수 있습니다. 원본은 1536×1024이며 웹 전송용 JPEG로 압축했습니다.

왼쪽 **API** 메뉴는 오늘(KST)·누적 요청 수, 응답 API가 반환한 입력·출력·캐시·추론 토큰, 실패 요청, 평균 응답 시간, 모델별 사용량과 최근 100건을 보여줍니다. 캐시 토큰은 입력에, 추론 토큰은 출력에 포함되므로 중복 합산하지 않습니다. 로컬 규칙 응답은 AI 토큰을 사용하지 않습니다.

사용량은 업데이트 이후 이 브라우저에서 보낸 게임 통신만 집계합니다. 별도의 localStorage 키에 저장하여 새 항해로 게임을 초기화해도 유지됩니다. 다른 기기나 앱의 요청, 이 함선 이미지 생성, 계정 잔액·실제 청구액은 집계하지 않습니다. HTTP 오류·타임아웃 등으로 usage를 받지 못하면 토큰을 0으로 추정하지 않고 미확인으로 기록합니다. 표시할 답변이 없는 경우에도 API가 usage를 반환했다면 해당 토큰을 기록합니다.

누적 합계와 모델 합계는 유지하며, 일별 합계는 최근 90일, 개별 내역은 100건을 보관합니다. 일별 모델 합계도 개별 내역 보관 수와 독립적으로 유지합니다. 대화 본문·API 키·접근 코드는 사용량 장부에 저장하지 않습니다. 여러 탭의 동시 쓰기에 대한 트랜잭션 저장소는 아니며, 서버·계정 단위 정산은 연결된 OpenAI 사용량 대시보드에서 확인하세요.

`usage.js`는 서버 응답 usage 정규화, 브라우저 집계와 사용량 패널을 담당합니다. 서버 응답은 공개 가능한 설정 모델과 토큰 수만 전달하며 API 키를 반환하지 않습니다.


## 조건부 랜덤 사건

기존 30시간 고정 구조 요청을 시간·위치·상태 기반 사건으로 교체했습니다. 판정은 UI 프레임이 아닌 게임 시간의 경계에서 진행합니다. 저장에 난수 상태를 함께 보관하므로 배속·화면 갱신·저장 후 재접속으로 결과를 다시 뽑지 않습니다.

| 규칙 | 초기 설정 |
| --- | --- |
| 시간 판정 간격 | 게임 시간 6시간 |
| 항해 기본 사건 확률 | 판정당 28% |
| 케플러·에코·장막으로 향하는 항로 | +15%p |
| 선체 50 미만 | +8%p |
| 사건 사이 최소 간격 | 12시간 |
| 동일 유형 재발 제한 | 36시간 |
| 외곽 탐사 추가 발견 | 탐사 완료 시 35%, 대기 시간 적용 |
| 항구 정박 | 강제 선택 없음. 판정당 10%로 현지 재고 감소 및 시장 보고 |
| 공개 방송 | 게임 시간 3~5시간 간격, API 호출 없음 |

사건 8종은 구조 요청, 잔해 구름, 이온 폭풍, 이동 상인, 순찰선 검문, 보급 컨테이너, 유적 신호, 적대 무장 함선입니다. 이온 폭풍은 외곽 항로, 순찰선은 일반 항로, 유적 신호는 에코·장막 탐사에 등장합니다. 사건은 가중치로 고르며 조건·대기 시간 때문에 실제 발생 빈도는 위 단일 판정 확률보다 낮습니다.

선택지에 비용·보상·항해 지연·손상 확률을 표시하고, 부족한 자원과 화물 공간을 사전에 검사합니다. 자원 부족 시에도 이탈·중계·안전 관측 등 진행 가능한 선택이 남습니다. 위험 선택의 결과는 버튼 확정 때 판정하며 한 번만 적용됩니다. 환경 사건 피해는 선체를 1 미만으로 내리지 않습니다. 전투에서는 선체 0에 도달하면 구조 예인됩니다. 이동 상인에게 매입한 화물 원가는 교역 장부의 평균 원가에 반영되며 해당 거래 자체는 사건 일지에 남습니다.

실행 중 사건이 있으면 시간·항해·수익·공개 방송이 정지합니다. 게임 내 로그 메뉴에서 판정 규칙과 누적 판정·해결 수를 확인할 수 있습니다.

## 통신 네트워크

통신 패널은 채널 목록과 메시지 피드로 구성됩니다. 기본 채널은 항성계 전체, 항성 연합, 헬리오스, 자유 항해 연맹입니다.

- **항성계 전체**: NPC 일상 방송, 실제 도착·탐사·사건·시장 보고가 올라오는 공개 피드. 실제 다른 플레이어의 채팅이 아닙니다.
- **공개 주파수 구독**: 교역 네트워크, 항로 안전망, 탐사자 라운지를 + 버튼으로 추가합니다.
- **사용자 채널**: 이름과 방송 주제를 지정하거나, 기존 세력에 연결하는 별도의 AI 대화 채널을 만듭니다. 최대 12개입니다.
- **방송 수신**: 공개 채널의 ▶ 버튼으로 1× 게임 시간을 진행해 새 방송을 받습니다. 정지 시 피드도 정지하며, 중요한 사건 발생 시 대응 패널로 이동합니다.
- **공개 게시**: 해당 주파수에 내 메시지를 남깁니다. NPC 피드는 규칙과 문장 템플릿으로 생성되며 AI 호출·토큰 비용이 발생하지 않습니다.
- **개별 AI 통신**: 세력 채널에서 전송할 때만 `/api/comms`를 호출합니다. 채널별 대화가 분리되며 최근 10개 사용자/AI 메시지만 전송합니다. 공개 피드 전체는 보내지 않습니다.
- **보관**: 채널별 최근 80개 메시지, 구독과 읽음 위치를 게임 저장에 보관합니다. 기존 세력 대화도 새 채널로 옮깁니다. API 사용량 장부는 별도로 유지합니다.

`events.js`는 조건·난수·선택지·결과를, `communications.js`는 채널과 방송 데이터를, `comms-ui.js`는 통신 HUD를 담당합니다.


## 현재 구역과 유형별 행동

항성계 지도 구성은 유지하고 실제 위치에 이중 광환·현재 위치 표식을 추가했습니다. 목적지 선택 표식과 구분되며 항해 중에는 이동 중인 노마드 표식으로 전환합니다. 현재 위치 또는 상단의 **현재 구역 행동**을 누르면 현지 패널이 열립니다. 다른 목적지를 누르면 행동 미리보기와 출항 버튼을 표시하며, 현지 서비스는 도착해야 실행할 수 있습니다. 도착하면 구역 행동 패널이 열리고 시간이 정지합니다.

| 구역 종류 | 현지 행동 |
| --- | --- |
| 정거장 | 거래, 보급, 수리, 장비 도크, 관할 팩션 연락. 시설 구매·구역 탐사 불가 |
| 거주 행성 | 궤도·지표 조사, 현지 시장, 보급·수리, 행정청 소유권 심사 |
| 항성 | 안전 관측 궤도에서 스펙트럼 관측. 착륙·교역·소유권 매입 불가 |
| 소행성대 | 광맥 탐사, 채굴 전초기지 건설 |
| 유적 | 고대 구조물 조사, 기술 부품 회수 |
| 성운 | 센서·신호 탐사 |

조사는 구역당 3회이며 첫 조사에 명예 +8과 해당 팩션 신뢰 +2(미지정 구역은 자유 연맹)를 받습니다. 이후 단계는 기존 탐사 자원 보상을 유지하고 최초 발견 명예를 반복 지급하지 않습니다. 탐사 진행도는 조사 가능한 5개 구역을 기준으로 표시합니다. 이전 저장의 정거장 조사 기록은 삭제하지 않습니다.

## 행성 매입과 주요 팩션

테라 노바 소유권은 **10억 CR, 성계 명예 10,000, 항성 연합 신뢰 60**을 모두 충족하고 현지에서 사건 없이 대기 중일 때 매입할 수 있습니다. 조건을 확인한 뒤 별도 매입 확정을 거칩니다. 자금만 차감하며 명예·신뢰는 소비하지 않습니다. 소유권과 기본 세수 **5,000 CR/h**가 자산에 반영됩니다. 세부 행정 정책은 아직 없습니다. 모든 정거장은 자금과 명예에 관계없이 구매가 불가능하며 엔진과 저장 검증에서도 이를 차단합니다.

| 주요 팩션 | 관할과 성향 | 신뢰·명예를 얻는 행동 |
| --- | --- | --- |
| 항성 연합 | 헤이븐·테라 노바, 행정과 민간인 안전 | 보급 계약 명예 +10/신뢰 +3, 물자 구조 명예 +15/신뢰 +2, 구조 중계 명예 +3/신뢰 +1 |
| 헬리오스 기업 | 조선소, 산업과 계약 이행 | 현지 광물 10t 조달 납품: 600 CR, 명예 +8/신뢰 +4 |
| 자유 항해 연맹 | 프리포트·케플러, 자치와 독립 탐사 | 프리포트에서 새 조사 단계 공유: 단계당 명예 +5/신뢰 +2. 같은 단계 중복 불가 |

팩션 패널에 조직 소개, 목표, 선호 행동, 관할, 다른 팩션과의 관계, 현재 신뢰와 연락관을 제공합니다. 세 팩션의 신뢰는 −100~100에서 따로 저장됩니다. 명예는 공통의 누적 공적입니다. 구조 지원은 자유 연맹 신뢰도 +1 올립니다. 팩션 간 관계 설명은 현재 세계관이며 자동 전쟁이나 영토 변화는 실행하지 않습니다.

기존 저장은 완료 계약과 과거 최초 조사에서 확인할 수 있는 공적을 복원하며 이전 자금·화물·채널·API 사용량을 유지합니다. `world-data.js`가 장소와 현지 행동을, `factions.js`가 팩션 설정·공적을, `map-ui.js`·`location-ui.js`·`faction-ui.js`가 해당 화면을 담당합니다.


## 상단 지역 뉴스

기존 지도를 유지하고 헤더 아래에 지역별 이슈를 보여주는 뉴스 티커를 추가했습니다. 거주 행성·정거장·항성·외곽 구역의 시세, 재고 부족, 관측 정보, 실제 조우와 교전 보고를 요약합니다. 항목을 클릭하면 해당 지역 정보가 열립니다. **성계 소식**을 누르면 정리된 목록을 볼 수 있습니다.

일반 안내는 현재 게임 상태에서 계산합니다. 실제 사건 소식은 생성 시점과 만료 시점을 저장하며, 같은 상황의 후속 소식으로 교체합니다. 소식은 성계 시간 기준으로 만료되고 최대 32건을 보관합니다. AI 호출은 없습니다. 마우스 올리기·키보드 포커스·일시정지 버튼으로 흐름을 멈출 수 있으며, 모션 감소 설정에서는 자동 흐름 대신 가로 스크롤을 제공합니다. 뉴스 일시정지는 성계 시간과 독립적입니다.

## 항해 조우와 전투 지휘

적대 무장 함선은 **항해 중에만** 확률적으로 조우합니다. 기존 전체 사건 확률은 유지하며, 적대 조우 선택 가중치는 일반 항로 12, 외곽 항로 28입니다. 이 수치는 직접적인 조우 확률이 아니라 다른 가능한 사건과 비교하는 가중치입니다. 기존의 구조·상인·순찰 조우도 유지됩니다.

조우 대응은 교전, 즉시 철수 시도, 통행료 200 CR 지불입니다. 전투를 시작하면 전투 지휘 패널에서 명령 하나씩 실행합니다. **전투 턴 동안 성계 시간·항해·수익·공개 방송은 정지**합니다. 에너지와 열, 아군·적군의 실드·선체, 다음 적 행동과 전투 기록을 표시합니다.

아래는 기본 지급 장비 기준입니다. 장비 교체 후 사격 수치·방어 회복·철수 성공률은 실제 장착 설계를 따릅니다.

| 명령 | 효과 |
| --- | --- |
| 조준 사격 | 명중 88%, 피해 20~28, 에너지 14, 열 +16 |
| 집중 포격 | 명중 68%, 피해 35~48, 에너지 30, 열 +32. 열 70 미만 필요 |
| 방어 태세 | 실드 +18, 에너지 +20, 반격 피해 60% 감소, 열 −25 |
| 긴급 철수 | 연료 3으로 성공 75%. 연료 부족 시 무추진 성공 40%. 실패 시 적 반격 명중률 50% |
| 항복·화물 투기 | 확정 이탈. 최대 250 CR과 화물 5t을 넘김 |

적은 명중률 82%로 일반 반격(12~18), 3번째 턴마다 집중 포격(22~30)을 합니다. 지속 교전 턴 종료 시 에너지 +9, 열 −10을 적용합니다. 실드가 피해를 먼저 흡수하고 잔여 피해가 선체를 손상시킵니다. 적 격퇴 시 현상금 550 CR, 명예 +12, 연합·자유 연맹 신뢰 +2를 받고 광물 3t을 회수합니다. 공간이 없으면 광물 대신 잔해 데이터 90 CR을 받습니다. 보상은 한 번만 지급됩니다.

교전 불능 시 영구 자산을 유지한 채 헤이븐으로 구조 예인합니다. 최대 500 CR을 정산하고 선체 25·최소 연료 25로 복구합니다. 교전 종료 후 결과를 확인하고 명시적으로 항해를 재개합니다. 현재 교전과 마지막 보고는 저장하며 재접속 시 난수 결과를 다시 뽑지 않습니다. 뉴스와 공개 안전망에도 조우·결과 보고가 반영됩니다. 전투 판정에 AI를 호출하지 않습니다.

`news.js`는 지역 이슈와 티커를, `combat.js`는 교전 규칙을, `combat-ui.js`는 전술 패널을 담당합니다.


## 함선 장비와 정거장 도크

무기·실드·엔진 3슬롯과 고정 전력 12 리액터를 도입했습니다. 기본 지급 장비 3개를 포함해 총 24종입니다. 희귀도는 일반 Lv.1, 고급 Lv.2, 희귀 Lv.3, 영웅 Lv.5의 고정 제품 설계 등급이며 경험치 강화나 랜덤 옵션은 없습니다. `equipment.js`의 명시적인 수치가 상점·항해·전투·저장 검증에서 공통으로 쓰입니다.

헤이븐·헬리오스 조선소·프리포트의 장비 도크에서 모든 구매 장비를 동일한 가격에 판매합니다. 기본 지급품은 계속 보관하며 판매하지 않습니다.

| 무기 계열 | 구성 | 역할 |
| --- | --- | --- |
| 레이저 | 펄스 레이저 / 추적 광선 / 프리즘 레이저 | 높은 명중률과 안정적인 피해 |
| 탄환 | 표준 함포 / 레일건 / 정밀 레일 포대 | 직사 화력과 균형형 전력 |
| 플라즈마 | 투사기 / 플라즈마 포 / 랜스 | 높은 피해와 발열 |
| 미사일 | 유도 미사일 / 시커 / 스톰 | 유도 명중과 낮은 열, 높은 에너지 사용 |

무기 12종·실드 6종·엔진 6종으로 총 24종입니다. 무기 탭에 전체·레이저·탄환·플라즈마·미사일 필터를 제공하며 상점과 보유 장비 모두에 적용합니다. 기존 보유 장비 ID와 성능은 유지합니다. 현재 탄환·미사일에 별도 탄약 재고는 없으며 표시된 사격 에너지를 소모합니다.

고급 장비는 900~1,100 CR, 희귀는 3,900~4,600 CR, 영웅은 12,500~14,500 CR입니다. 한 슬롯당 한 개만 장착하며 전력 합계 12를 넘을 수 없습니다. 예를 들어 플라스마 랜스(6)+기본 실드(3)+기본 엔진(3)은 가능하지만 세 슬롯 모두 최고 등급으로 맞출 수 없습니다. 레일건은 단발 화력, 광선은 명중, 보루는 용량, 순환은 방어 회복, 요격 엔진은 속도, 장거리 엔진은 연료 효율에 특화됩니다.

장비 메뉴 또는 현지 정거장 행동의 **함선 장비 도크**에서 현지 상점과 보유 장비를 전환합니다. 실제 능력치와 장착 대비 차이, 전력·가격·장착 불가 사유를 표시합니다. 구입 후 직접 장착하며, 장착하지 않은 구매품은 정가의 60%에 판매할 수 있습니다. 기본 장비는 보관하며 판매할 수 없습니다. 동일 제품 중복 구입 불가, 장비는 화물 40t과 별도로 보관합니다. 도크 작업은 사건 없이 정거장 정박 중일 때만 가능합니다.

실드 최대 용량과 방어 회복이 실제 전투에 반영됩니다. 교체로 충전량이 늘지 않으며 하위 용량으로 교체하면 초과분을 잃습니다. 현지 유료 충전은 1당 2 CR, 도착 시 자동 완충입니다. 엔진은 항해 시간·출항 연료·추진 철수 확률과 거래 항로 수익 예상에 반영합니다. 이미 출항한 항로는 유지합니다. 무추진 탈출 확률은 40%입니다.

무기의 조준 피해·명중·에너지·발열을 실제 판정에 적용합니다. 집중 포격은 최소 피해 1.75배·최대 피해 약 1.714배를 정수 반올림, 명중 −20%p, 에너지 약 2.143배 반올림, 발열 2배입니다. 포격은 현재 열 70 미만이고 발열을 더해 100을 넘지 않을 때만 가능합니다. 기존 기본 함포 수치는 유지됩니다. AI 호출 없이 모든 장비 효과를 엔진에서 계산하며, 기존 저장에는 원래 성능의 기본 장비를 지급해 자금·항로·진행 중 전투를 보존합니다.


사이드 메뉴는 모든 버튼의 아이콘·글자·패딩이 고정 높이 안에 들어가도록 정리했습니다. 데스크톱 높이 56px, 좁은 화면 높이 52px로 통일하고 아이콘 26/24px, 라벨 12px 행을 분리합니다. 높이가 부족하면 메뉴 부분만 세로 스크롤되며 도움말은 하단에 유지합니다.


적 함선은 한 번 생성한 붉은 와이어프레임 전술 스캔 이미지를 `assets/raider-wireframe.jpg`에 저장해 전투 패널에서 재사용합니다. 호출명에 관계없이 현재 무등록 레이더의 공통 외형이며, 전투 시작·턴 진행·재접속 시 이미지 생성 API를 호출하지 않습니다. 아군 노마드 이미지는 유지합니다.


## 전투 공격 연출

공격 명령 뒤 아군 사격 → 명중/빗나감 → 적 반격 순서로 짧은 연출을 재생합니다. 장착 무기 계열에 따라 레이저 광선, 탄환 점사, 플라즈마 탄, 미사일 추진 궤적을 구분하며 집중 포격은 다중 사격으로 표현합니다. 실드 피격은 푸른 방어막 파동, 선체 피격은 섬광·짧은 진동과 피해 수치로 표시합니다. 체력과 실드 막대는 각 명중 시점에 갱신됩니다. 방어 명령은 방어막 펄스로 표시합니다.

엔진은 명령을 즉시 판정·저장하고 `effects`를 반환하며 브라우저는 그 실제 결과만 재생합니다. 연출 데이터는 저장 파일에 추가하지 않고 새 난수·이미지 생성·AI 호출도 하지 않습니다. 연출 중 명령 중복 실행을 막고, 패널 전환·닫기·탭 숨김 시 남은 연출을 취소·정리합니다. 모션 감소 설정에서는 광선 이동·섬광·진동을 생략하고 결과 텍스트를 짧게 표시합니다. `combat-effects.js`는 게임 상태를 수정하지 않는 표시 전용 모듈입니다.

## 전담 담당자와 팩션 임무

각 팩션의 기존 연락관이 함장 전담 담당자가 됩니다. 연합은 **윤서진**, 헬리오스는 **레아**, 자유 항해 연맹은 **카이**입니다. 이름·직무·업무 성향과 담당 임무 완료 수를 팩션/임무 패널에 표시하고 같은 인물이 개별 채널에서 의뢰와 진행 안내를 보냅니다. 담당자의 별도 개인 호감도나 교체는 아직 없습니다.

- **수락 경로:** 팩션창의 담당자 의뢰 카드에서 조건을 검토하고 명시적으로 수락합니다. 먼저 도착하는 전담 메시지에도 의뢰 조건 링크가 있으며 같은 임무 패널로 연결됩니다. 정거장의 현지 행동에는 담당자 임무 게시판을 추가했습니다.
- **제안과 갱신:** 팩션별 운송·탐사·현상금 각 1종, 총 9개 설계입니다. 최초 연결 때 담당자 3명이 소개와 제안을 보냅니다. 이후 게임 시간 24시간마다 현재 제안 안내를 각 1건 보냅니다. 읽거나 패널을 열 때 난수를 소비하거나 메시지를 반복 생성하지 않습니다. 여러 날이 지난 저장은 현재 날짜의 안내만 보냅니다. 메시지·임무 생성은 AI를 호출하지 않습니다.
- **진행 제한:** 기존 식량 보급 계약까지 합쳐 동시 3개. 수락한 일반 임무에는 기한이 없으며 제안 목록만 날짜별로 갱신됩니다. 같은 날짜의 동일 의뢰는 완료/포기 후 다시 수락할 수 없고, 진행 중인 설계도 중복 제안하지 않습니다.
- **운송:** 발주 정거장에서 무료 봉인 임무 화물을 수령한 뒤 목적지에 전달하면 보수를 받습니다. 화물은 일반 매매 재고와 분리하되 같은 40t 공간에 포함합니다. 거래·탐사 회수·사건 보급품·전투 잔해 회수 모두 남은 공간을 확인합니다. 봉인 화물은 판매할 수 없고 일반 상품의 평균 매입 원가에 포함되지 않습니다.
- **탐사:** 지정 구역에서 임무용 정밀 스캔에 연료 5를 사용하고 발주 정거장에 귀환해 보고합니다. 일반 구역 탐사 3회 제한과 별개이며 스캔 자체의 일반 탐사 보수는 없습니다. 이미 일반 탐사를 끝낸 구역도 임무를 수행할 수 있습니다.
- **현상금:** 지정 구역 도착 후 `지정 표적 추적`을 실행하면 연료 3으로 명시적인 교전을 시작합니다. 현지 복귀용 2시간 추적 항로를 만들며 지정 적 함선의 격퇴만 임무 진행으로 인정합니다. 일반 해적 격퇴, 통행료, 항복, 철수는 목표 완료가 아닙니다. 철수/패배 시 임무는 유지되어 다시 준비할 수 있습니다. 교전 현상금 550 CR과 발주처에 귀환 보고한 뒤 받는 임무 보수는 별도이며 화면에 함께 명시합니다.
- **정산과 포기:** 보수·명예·팩션 신뢰는 전달/귀환 보고 버튼으로 한 번만 지급합니다. 포기는 확인 후 실행하며 자금·명예·신뢰 불이익 없이 무보상 처리합니다. 봉인 화물은 발주처 회수 처리로 제거합니다. 선급금·긴급 기한·호위·구조·회수 임무는 이번 범위에 포함하지 않습니다.

진행 임무의 다음 목적지와 현지 행동은 임무 패널과 해당 구역 행동에 모두 표시합니다. 완료/포기 기록은 최근 30건, 담당자별 완료 수는 누적 보관합니다. 기존 식량 5t/650 CR 보급 계약과 저장·자산·통신 이력은 유지하며 신규 임무 데이터와 안내만 추가합니다. `missions.js`가 임무 상태/검증/정산, `mission-ui.js`가 담당자/게시판/진행 목록, `cargo.js`가 공유 화물 용량을 담당합니다.

## 승무원 · 함내 개인 대화

일반 선원은 별도로 모집하지 않습니다. 함선 AI가 기본 항해·사격·정비·화물 처리를 수행하고, 이름이 있는 핵심 승무원만 탑승합니다. 함급 정원은 소형 탐사선 2명, 호위함 3명, 구축함 4명, 순양함/주력함 5명이며 함장은 별도입니다. 현재 소유·운용 선체는 노마드(소형 탐사선, 2명)이고 다른 함급 구매·전환은 아직 없습니다. 기존의 고정 ‘4명’ 표시는 실제 탑승 인원으로 교체했습니다.

승무원 패널은 탑승자 관리, 인물 프로필, 접을 수 있는 전문 분야·업무 배치, 인물별 대화로 구성합니다. 목록과 프로필에 4:5 비율의 빈 초상화 슬롯을 마련했습니다. 현재 인물 이미지는 생성하지 않았으며 `data-portrait-id`로 나중에 연결할 수 있습니다.

| 모집 후보 | 주 전문 / 보조 전문 | 계약금 | 급여(게임 시간 하루) |
| --- | --- | ---: | ---: |
| 서하린 | 항해·탐사 / 지휘·협업 | 420 CR | 24 CR |
| 윤가온 | 기관·동력 / 군수·정비 | 460 CR | 26 CR |
| 강태오 | 전술·방어 / 지휘·협업 | 540 CR | 30 CR |
| 민유리 | 군수·정비 / 항해·탐사 | 360 CR | 20 CR |
| 이도현 | 지휘·협업 / 전술·방어 | 580 CR | 32 CR |

모집은 사건 없이 해당 후보가 있는 거래소에 정박한 상태에서 실행하며, 하선·업무 변경은 정거장에서 진행합니다. 승함은 계약 내용을 확인한 뒤 확정하고, 기본적으로 주 전문 모듈에 자동 배치합니다. 부서당 한 명만 배치하며 보조 전문은 해당 부서 효과의 50%, 비전문 배치는 추가 효과 없이 함선 AI의 기본 성능을 유지합니다. 변경 전후 능력치를 미리 볼 수 있습니다. 하선은 별도 확인하며 계약금 반환은 없고 대화·신뢰는 보관합니다. 재고용하면 계약금을 다시 지급합니다.

| 담당 모듈 | 주 전문 기준 효과 |
| --- | --- |
| 지휘·협업 | 방어 명령 실드 회복 +2, 추진 철수 +4%p |
| 전술·방어 | 사격 명중 +4%p, 방어 명령 실드 회복 +3 |
| 기관·동력 | 지속 교전 턴 종료 에너지 +2, 냉각 +2 |
| 항해·탐사 | 출항 연료 −8%, 항해 속도 +5% |
| 군수·정비 | 연료 보급·선체 수리·실드 충전 비용 −12% |

실제 항해·전투·정비 계산에 반영하며 장비의 원래 데이터는 변경하지 않습니다. 명중률은 최대 99%, 추진 철수는 최대 98%입니다. 함선 패널에는 5개 모듈의 담당자/AI 운용 상태와 함급별 정원 기준을 표시합니다. 별도의 액티브 승무원 전투 명령이나 장비 슬롯 확장은 이번 범위에 포함하지 않습니다.

급여는 게임 시간이 흐른 만큼 시간 비례로 자동 지급합니다(일급/24). 정지·교전 턴·오프라인 시간에는 발생하지 않고 정박 중 시간 진행에는 발생합니다. 자금이 모자라면 잔액을 음수로 만들지 않고 미지급 급여를 기록하며 사람의 전문 효과만 정지합니다. 기본 AI 운용과 대화는 유지되고 정거장에서 미지급분을 정산하면 효과가 복구됩니다. 하선해도 이미 발생한 미지급분은 남습니다.

- 상태 보고·임무 브리핑·전문가 조언·개인 이야기는 규칙 기반 로컬 메시지이며 API를 호출하지 않습니다.
- 저연료·선체 위험·급여 미지급 경고는 조건과 게임 시간 24시간 재알림 제한으로 전달합니다. 도착·교전 준비·임무/교전 완료 소감도 보냅니다.
- 자유 대화는 기존 `/api/comms`에 `crewId`로 요청하며 팩션 수신자와 혼용할 수 없습니다. 같은 접근 코드·속도 제한·모델·타임아웃·실제 사용량 반환을 공유합니다. 선택한 인물의 최근 사용자/AI 메시지 10개와 작은 상태 요약만 전송합니다. API 키가 없으면 로컬 인물 응답을 제공합니다.
- 인물별 최근 메시지 60개와 읽음 상태를 따로 보관합니다. 승무원 통신도 API 사용량 메뉴에서 인물 이름과 실제 토큰을 집계합니다.
- 대화는 명령·자금·신뢰를 바꾸지 않습니다. 수락 때부터 함께한 임무 완료 시 신뢰 +3, 교전 승리 시 +1을 한 번 지급합니다. 신뢰 10에서 인물별 짧은 로컬 개인 이야기가 열립니다. 기존 저장에 승무원을 임의 배치하거나 비용을 청구하지 않습니다.

`crew-data.js`는 함급·후보·전문 효과, `crew.js`는 모집/급여/신뢰/보고/저장 검증, `crew-ui.js`는 초상화 슬롯과 인물별 대화 패널을 담당합니다.

## 장소별 영입 · MBTI 성향

승무원 메뉴에서는 탑승자만 관리합니다. 모집은 현재 항구의 거래소 → 인력 중개소 또는 구역 행동의 현지 인력 중개소로 진입합니다. 항해·사건 중 계약할 수 없으며 다른 장소 후보를 원격 고용할 수 없습니다. 초상화 빈 프레임은 유지합니다.

- 헤이븐/프리포트: 서하린(INTP), 강태오(ISTJ)가 게임 시간 48시간마다 서로 항구를 옮깁니다.
- 헬리오스: 윤가온(ISTP). 테라 노바 시장: 민유리(ESFJ).
- 에코/장막 외곽 조우·탐사에 특수 조난 신호가 포함됩니다. 연료 2로 이도현(INFJ)의 구조를 지원하면 구조대가 헤이븐으로 이송합니다. 이후 헤이븐 중개소에서 기존 계약금 580 CR/급여 32 CR의 계약을 제안할 수 있습니다. 구조 자체로 자동 승함하거나 보상을 중복 지급하지 않습니다. 무시하면 이후 재발할 수 있고, 구조 성공 이후는 발생하지 않습니다.

후보의 이름·MBTI·능력·이력은 순회나 저장/불러오기로 재생성하지 않습니다. 첫 만남 장소·시각과 구조 완료를 저장합니다. 이미 탑승한 기존 인물은 새 모집 조건과 관계없이 유지합니다. MBTI는 말투·가치관·개인 위험 성향과 함께 로컬/AI 대화에 전달되며 능력치나 선악을 결정하지 않습니다. 모집·순회·구조·보고에는 AI API를 호출하지 않습니다.

## 함장 데이터 패드 · 지속 연락처

왼쪽 **데이터** 메뉴는 태블릿 형태의 전용 패널을 엽니다. 홈의 연락처/성계 소식/항해 일지/API 사용량 앱을 전환하며, 기존 소식·일지·사용량 링크도 이 패드의 해당 앱으로 연결됩니다. 거래·항해·장비·승무원 배치는 기존 지휘 패널에서 실행합니다.

후보 프로필을 현지에서 열면 최초 만남이 자동 등록됩니다. 영입 검토를 보류해도 데이터 → 연락처에서 인물의 빈 초상화 슬롯, MBTI·이력·최초 만남과 개인 대화 기록을 확인하고 원격 메시지를 보낼 수 있습니다. 대화는 영입/급여/신뢰를 변경하지 않습니다. 실제 승함은 해당 인물이 있는 현지 중개소에서만 확정하며, 근처에 있을 때 연락처에 현지 계약 검토 링크가 나타납니다. 이미 만난 인물은 순회·하선·저장/불러오기 이후에도 남고, 기존 저장의 승무원 대화 기록도 연락처로 인식합니다. 아직 만나지 않은 인물은 목록에서 노출하거나 연락할 수 없습니다. 팩션 전담 연락관 3명도 같은 연락처 화면에서 기존 통신 채널로 연결됩니다.

원격 대화는 기존 인물별 메시지·접근 코드·API 사용량 기록을 공유합니다. AI에는 현재 탑승 여부와 최초 만남을 전달하고, 미영입 상대를 이미 승함한 승무원처럼 말하지 않도록 구분합니다. `data-ui.js`는 태블릿 프레임·앱 홈·연락처 목록·개인 연락 화면을 담당합니다.

## AI 항성계 탐색 · 규칙 버전과 생성 인물

왼쪽 **성간**에서 인접 미확인 좌표의 **AI 탐색 개시**를 선택합니다. `탐색 중 → AI 응답 검증 → 발견 완료`로 진행하며, 발견 후 별도의 성간 항해(연료 18, 18h)를 설정합니다. 아스테리온은 시작 항성계로 유지합니다. 새 성계에서도 현지 항해·거래·보급·탐사·장비·행성 구매·승무원 영입과 대화를 기존 엔진으로 실행합니다. 무인 성계는 보급이 없으므로 복귀 연료를 확보하고, 고립되면 긴급 예인으로 아스테리온에 복귀할 수 있습니다.

**실제 생성은 AI가 담당합니다.** `/api/explore`에서 행성·정거장 수, 천체 종류, 문명권/변경/미개척, 위험도, 현지 운영 주체와 주요 팩션 영향력, 시장 가격, 인물의 이름·성인 나이·MBTI·외형 설정·전문 분야·계약금·급여·가치관·말투·이력·개인 목표를 제안합니다. 엔진은 형식·범위·고정 제약을 검증하고 위치 좌표/고유 ID/실행 가능한 모듈과 연결합니다. 이름만 AI가 정하고 전체 구성을 엔진이 대신 뽑는 구조가 아닙니다. 허용하지 않은 효과나 시설, 과도한 수치와 단일 팩션 독점은 거부합니다.

데이터 패드 → **세계 생성 설정**에서 행성/기타 구역 범위, 정거장/모집 후보 상한, 쌍성/희귀 요소 비중 지침, 분위기를 수정합니다. 비중은 AI에 전달하는 방향 지침이며 통계적으로 강제한 출현 확률은 아닙니다. 0으로 설정하면 해당 요소를 금지합니다. 무료 **로컬 규칙 샘플**은 화면과 범위 확인용이며 실제 성계로 저장하거나 AI 결과인 것처럼 표시하지 않습니다. API 키/접근 코드가 없을 때 실제 생성은 실패 안내하며 로컬 결과로 자동 대체하지 않습니다.

좌표/우주 시드/규칙 스냅샷과 탐색 요청을 저장합니다. 진행 중 새 규칙을 저장해도 기존 요청은 원래 버전으로 계속됩니다. 실패/창 닫기 후 재개 버튼으로 명시적으로 재요청하며 추가 AI 비용이 발생할 수 있습니다. 같은 서버 인스턴스에서 10분 이내 같은 요청은 처리 중 요청을 공유하거나 완료 결과를 재사용합니다. 서버 인스턴스/재배포를 넘는 결제 중복 방지는 보장하지 않습니다. 완료된 결과는 브라우저 저장에 고정되며 재방문에는 생성 요청이 없습니다. 규칙 변경은 새 탐색부터 적용됩니다. 아직 방문하지 않은 좌표를 미리 전부 생성하지 않습니다. 좌표를 따라 계속 확장할 수 있지만 보존 용량은 브라우저 저장 공간의 제약을 받습니다.

생성 인물은 실제 정원/급여/업무 효과/개별 대화/연락처를 사용하며, 다른 성계로 이동해도 인물과 대화를 유지합니다. MBTI와 외형 설정은 기록하고 초상화 프레임은 비워 둡니다. 이번 단계의 생성 인물 영입은 유인 거점의 계약 방식입니다. 별도 절차적 구조 인물, 숨겨진 구역의 단계별 공개, 생성형 임무, 팩션의 지속적인 보급망/영향력 시뮬레이션은 후속 작업입니다. 기존 아스테리온의 임무와 특수 구조 사건은 유지합니다.

생성 API는 기존 `OPENAI_API_KEY`, `GAME_ACCESS_CODE`, `OPENAI_MODEL`을 공유하고 요청을 IP당 분당 3회 제한합니다. 실제 응답 사용량과 실패 시 확인된 토큰을 API 사용량에 기록합니다. 모의 AI 응답으로 검증하며 테스트 과정에서 실제 유료 호출을 실행하지 않습니다.


## 수동 이미지 생성 · 이미지 스튜디오

데이터 → **이미지 스튜디오**에서 노마드, 발견한 행성, 만난 승무원과 팩션 연락관을 선택합니다. 함선/행성 정보와 초상화에서도 바로 열 수 있습니다. 세계·인물 생성과 이미지 생성은 독립적이며 자동으로 유료 요청하지 않습니다. 프롬프트를 수정하고 품질을 선택한 뒤 **AI 이미지 1장 생성**을 명시적으로 눌러 요청합니다. 프롬프트는 설정 기반이며 원본 이미지를 참조하는 편집 기능은 아닙니다. 동일 인물이나 디자인의 완전한 일치는 보장되지 않습니다.

서버의 기존 OPENAI_API_KEY 및 GAME_ACCESS_CODE를 사용합니다. OpenAI 이미지 생성은 gpt-image-2 모델을 사용합니다. 낮음/보통/높음은 해당 모델의 quality 설정이며 모델 선택과 별개입니다. 기존 OPENAI_IMAGE_MODEL 환경 변수는 사용하지 않습니다. /api/images는 인증, 입력 제한, 동시 요청 제한과 인스턴스 내 분당 3회 제한을 적용합니다. 1장 JPEG 결과를 반환하며 실제 사용량은 기존 API 집계에 기록됩니다. 서버 인스턴스를 넘는 중복 결제 방지나 브라우저를 닫은 뒤 생성 복구는 보장하지 않으며 실패 후 자동 재시도하지 않습니다.

생성 결과는 **미리보기 보관 → 사용자 적용** 순서입니다. 원래 이미지 파일은 유지하며 대상별 최대 12장과 프롬프트/모델/생성 시간을 보관합니다. 이전 이미지 재적용, 원본 또는 빈 초상화 복원, 다운로드와 개별 삭제를 지원합니다. 이미지는 우주 시드·대상 ID로 구분하여 현재 브라우저 IndexedDB에 저장하고 게임의 localStorage 저장에는 이미지 바이트를 넣지 않습니다. 다른 기기와 자동 동기화하지 않으며 브라우저 데이터 삭제 시 소실될 수 있으므로 필요한 이미지는 다운로드하세요. 저장 실패 시 현재 적용 이미지를 유지합니다. 새 항해는 이전 우주의 이미지를 노출하지 않습니다.

NovelAI API는 아래 설정으로 연결합니다. 이미지 업로드는 추후 추가합니다. 이 기능의 검증은 모의 API 응답으로 진행하며 실제 유료 생성은 테스트에서 호출하지 않습니다.

### API 사용량의 예상 비용

데이터 → API 사용량에서 오늘/누적 예상 USD, 모델별 소계와 최근 요청별 비용을 표시합니다. 2026-10-26에 확인한 공식 표준 토큰 요금으로 계산하며 캐시 입력은 할인 단가, 추론은 이미 출력에 포함되어 중복 합산하지 않습니다. 현재 요금표는 gpt-4.1-mini(2025-04-14 스냅샷 포함), gpt-6-astra, gpt-6.1-sol, gpt-6-luna와 텍스트 입력만 있는 gpt-image-1-mini 생성을 지원합니다. 미지원 모델/사용량 누락/이미지 모달리티 미확인 요청은 0원으로 간주하지 않고 산정 불가로 구분합니다. 현재 이미지 API는 텍스트 프롬프트만 전송하므로 이미지 입력 토큰이 0인 내역에서만 비용을 계산합니다.

과거 텍스트 요청은 100건으로 제한된 최근 기록 대신 전체 모델별 토큰 누계로 추정하여 누락을 피합니다. 신규 비용 누계는 일별/모델별로 지속 보관합니다. 이미 과금된 실패도 토큰을 받았으면 포함하며, 시간 초과와 미확인 요청은 소계에 포함할 수 없음을 표시합니다. 실제 청구액/세금/환전/프로젝트 할인/특별 서비스 등급을 조회하는 기능은 아니며 공식 사용량 대시보드와 요금표 링크를 제공합니다.

공식 근거: https://developers.openai.com/api/docs/models/gpt-4.1-mini · https://developers.openai.com/api/docs/models/gpt-image-1-mini · https://developers.openai.com/api/docs/pricing


### NovelAI 연결

Vercel 프로젝트의 환경 변수에 NOVELAI_API_TOKEN을 추가하고 재배포합니다. NovelAI의 User Settings → Account → Get Persistent API Token에서 발급한 토큰을 사용합니다. 토큰을 새로 발급하면 이전 토큰은 무효화되므로 이미 다른 곳에서 사용 중이면 기존 토큰을 재사용하세요. GAME_ACCESS_CODE는 기존 게임 통신 접근 코드를 사용합니다. NovelAI 토큰은 서버에만 저장하고 UI에는 설정 여부만 공개합니다.

이미지 스튜디오의 서비스에서 NovelAI를 선택한 뒤 영문 프롬프트, 네거티브 프롬프트, 선택적 시드(빈 값은 무작위)를 입력합니다. OpenAI/NovelAI의 편집 중인 프롬프트는 대상별로 분리하며 자동 번역 API는 호출하지 않습니다. 반실사 애니 스타일 기본 문구와 대상 설정을 제공하되 한국어 설정은 필요에 따라 영문으로 편집하세요. 기본 서버 모델은 nai-diffusion-4-5-full이며 NOVELAI_IMAGE_MODEL로 같은 V4/V4.5 요청 형식을 지원하는 모델 ID를 지정할 수 있습니다. V5 등 다른 요청 형식의 모델은 별도 검증이 필요합니다.

생성은 직접 버튼을 누를 때 한 장씩 요청합니다. 28 steps, k_euler_ancestral, scale 5, 인물 832×1216 / 나머지 1216×832를 사용합니다. GET /api/images에서 선택한 제공자의 연결 설정 여부를 확인합니다. JSON 응답 협상을 통해 PNG/WebP를 받으며 서명과 크기를 검사합니다. 기존 미리보기·선택 적용·원본 복원·보관과 다운로드를 유지하며 NovelAI 결과에 시드와 네거티브 프롬프트도 보관합니다.

Anlas/구독 혜택은 계정 조건에 따라 다르므로 무료라고 단정하거나 USD를 임의 계산하지 않습니다. API 사용량에는 NovelAI 모델과 요청 성공/실패, Anlas 방식임을 표시하고 토큰 및 USD는 산정 불가로 둡니다. 자동 재시도나 OpenAI로 유료 대체 요청은 하지 않습니다. 테스트는 모의 응답만 사용하며 실제 토큰 설정·인증·유료 생성은 별도 확인이 필요합니다.

공식 API: https://image.novelai.net/docs/index.html · https://image.novelai.net/docs/doc.json
토큰 발급: https://docs.novelai.net/en/text/usersettings/account/


## Supabase DB · 개인 클라우드 보관함

데이터 → 클라우드 보관함에서 현재 게임·이 우주의 생성 이미지 전체·적용 선택·프롬프트 편집본·공통 화풍을 수동 저장하고, 최신 20개 저장본 중 하나를 골라 복원합니다. 이미지 바이트는 비공개 Storage에 콘텐츠 해시 파일명으로 저장하고, DB에는 게임 JSON과 이미지 메타데이터/참조만 저장합니다. 같은 게임 접근 코드를 쓰는 개인 저장소이며 별도 사용자 계정 로그인/다중 사용자 분리는 이번 단계에 포함하지 않습니다. 원래 브라우저 저장은 유지하고, 이미지 생성·편집 뒤 클라우드 저장 버튼을 눌러야 다른 기기에서 복원할 수 있습니다. 자동 동기화는 없습니다.

### 초기 연결

1. Supabase 프로젝트를 만들거나 기존 프로젝트를 선택하고, SQL Editor에서 db/001_archive.sql을 실행합니다. asterion_archives 테이블과 asterion-art 비공개 버킷을 준비합니다. anon/authenticated에 테이블 권한을 부여하거나 공개 버킷으로 바꾸지 마세요.
2. Vercel 프로젝트의 Production 환경 변수에 SUPABASE_URL(https://프로젝트.supabase.co), SUPABASE_SERVICE_ROLE_KEY(서버 전용 service_role 키)를 설정합니다. 기존 GAME_ACCESS_CODE도 필요합니다. API 키를 프런트 코드, 저장본 또는 채팅에 붙이지 마세요.
3. 기존 프로젝트를 재배포하고 클라우드 보관함에서 접근 코드를 입력한 뒤 저장본 목록 확인으로 실제 DB 연결을 점검합니다. 연결 플래그는 환경 변수 유무만 확인하며 SQL 적용 여부까지 보장하지 않습니다.
4. 원래 이미지를 가진 브라우저에서 현재 기록을 클라우드에 저장합니다. 다른 기기에서는 같은 코드로 목록 확인 → 복원 내용 검토 → 현재 기록 백업 후 복원을 선택합니다.

복원 검토 화면에서 `백업 없이 불러오기`와 `현재 기록 백업 후 불러오기`를 선택합니다. 백업을 선택한 경우에만 현재 게임을 클라우드에 새 버전으로 추가합니다. 기존 원격 저장본을 덮어쓰지 않으며 삭제는 보관함의 별도 확인을 통해 실행합니다. 조회·업로드·저장·이미지 다운로드는 서버 인증 뒤 처리하며 서버 키는 브라우저로 전송하지 않습니다. 이미지 업로드가 실패하면 DB 저장본을 발행하지 않습니다. 이미지 다운로드와 저장본 검증을 끝내기 전에 현재 게임을 바꾸지 않습니다. 브라우저 저장이 실패하면 이미지·게임 복원을 되돌립니다. 백업을 선택했다면 사전 클라우드 백업도 남습니다. 현재 API는 이미지당 약 3MB, 메타데이터/게임 합계 2MB, 대상 200개·대상별 이미지 12장을 제한합니다. 목록은 최근 20개만 표시하지만 오래된 저장본을 자동 삭제하지 않으므로 저장소 용량은 별도 관리해야 합니다. 중단된 업로드 후 참조되지 않은 콘텐츠 파일은 남을 수 있습니다.

현재 검증은 모의 DB/Storage 응답 기준입니다. Supabase 프로젝트 연결과 환경 변수 설정 없이 실제 DB가 생성되거나 데이터가 업로드된 것으로 표시하지 않습니다. 설정 전 화면은 DB 연결 대기로 표시합니다. 공식 자료: https://supabase.com/docs/guides/api · https://supabase.com/docs/guides/storage/buckets/fundamentals · https://supabase.com/docs/guides/storage/security/access-control

### 전체 저장 일관성
자동 체크포인트, 수동 슬롯, 내보내기 파일은 게임 상태·현재 우주의 이미지 원본/버전/active 선택·프롬프트 설정을 함께 보관합니다. 로컬 전체 저장은 `asterion-full-saves-v1` IndexedDB에 저장하며 일반 localStorage 게임 기록도 호환용으로 유지합니다. 이미지 적용/삭제/원본 복원도 전체 체크포인트를 생성합니다. 파일은 `asterion-full-save` v1 형식이며 105MB 이하입니다. 클라우드 업로드도 같은 전체 저장 검증을 먼저 거칩니다. 전체 복원 전에 `before-restore` 백업을 만들며 화면에서 다시 불러올 수 있습니다. 구버전 상태 전용 슬롯/파일은 명시적으로 안내하고 기존 이미지 보관함을 지우지 않습니다. 구버전 저장 당시 포함되지 않았던 이미지를 복구할 수는 없으므로 원래 이미지가 있는 기기에서 전체 저장본을 새로 만들어야 합니다. 브라우저 저장과 클라우드 업로드는 여전히 별도 동작이며 자동 클라우드 동기화는 하지 않습니다.

### 클라우드 보관함 관리
저장 내용 보기는 저장본의 게임·이미지 선택·프롬프트·외부 링크를 읽기 전용으로 표시하며, 이미지 원본은 요청할 때만 내려받습니다. 사용량 조회는 private `asterion-art` 버킷의 metadata.size 합계와 저장본 개수입니다. DB 물리 용량·다른 버킷·외부 링크 파일 크기·계정 요금제 한도는 포함하지 않습니다. 목록이 20,000개/25초를 넘으면 일부 집계임을 표시합니다. 저장본 삭제는 확인한 UUID 한 건을 service_role로 삭제하며 공유 이미지 원본은 보존합니다. 따라서 이미지 저장소 용량 정리는 Supabase Storage에서 별도로 관리해야 합니다. DELETE 권한이 없는 기존 설치는 `grant delete on public.asterion_archives to service_role;`을 SQL Editor에서 적용합니다.

### 함선 시장과 조선소 · 일반 함선

조선소 패널은 왼쪽 `조선소`, 내 함선/자산의 바로가기, 헤이븐·헬리오스·프리포트의 구역 행동에서 엽니다. 일반 함선은 노마드, 캐러밴, 케스트럴, 몰, 패스파인더 5척을 지원합니다. 상위 4등급은 각 5척의 이름과 역할만 미리 전시하며 아직 구매·건조되지 않습니다.

완제품 구매 또는 설계도 구입 → 원재료 확보 → 합금/코어 제작 → 건조 발주 → 게임 시간 경과 → 발주 조선소 인수 순서입니다. 광물은 소행성대에서 반복 채굴(연료 5, 3h), 스크랩은 소행성대·유적·성운에서 일반 인양(연료 4, 2h)으로 확보합니다. 몰은 채굴량과 스크랩 획득이 증가합니다. 합금은 광물 4t+50 CR(1h), 코어는 합금 2개+기술 부품 3t+150 CR(2h)입니다. 원재료는 실제 화물에서 소비하고 가공 자재는 조선소 공동 창고에 보관합니다. 임무용 봉인 화물은 제작에 소비하지 않습니다.

건조는 하나씩 진행하며 게임 시간에만 진척됩니다. 발주 후 자재·공임은 소비되고 취소할 수 없습니다. 다른 활동 중에도 건조 시각은 진행하며 완료 후 원래 조선소에서 인수합니다. 같은 설계는 한 척씩 소유합니다. 기함 교체는 보관 조선소에서만 가능하고 공용 장비·화물·승무원을 이전합니다. 초과 적재·승무원 정원·리액터 한도는 교체 전에 확인하며, 비활성 함선은 해당 조선소에 남습니다. 함선별 선체·연료·실드가 보존되고 새 함선의 실드는 충전이 필요합니다. 매각은 비활성 함선만 가능하며 장비와 설계도는 남습니다.

`fleet` 상태에 보유선·기함·설계도·자재·건조 작업을 저장합니다. 이전 저장은 기존 진행과 장비를 보존한 노마드 한 척으로 이전됩니다. 기함 성능은 항로, 전투, 화물 제한, 거래, 봉인 화물, 채굴과 승무원 정원에 적용합니다. 전체 파일 및 클라우드 저장에도 같은 `fleet` 상태가 포함됩니다.

함선 이미지는 조선소의 각 함선 카드에서 **함선 이미지 생성·관리**로 엽니다. 일반 5종은 구매 전에도 NovelAI/OpenAI로 수동 생성할 수 있으며, 역할별 전용 영문 프롬프트를 제공합니다. 생성 후 미리보기에서 적용하면 조선소와 기함 표시가 함께 변경됩니다. 기존 사용자 프롬프트는 유지하므로 새 기본값을 쓰려면 **기본 프롬프트 불러오기**를 누르세요. 적용 이미지와 보관 버전은 기존 전체 저장·클라우드 저장에 포함됩니다.
